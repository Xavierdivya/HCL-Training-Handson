## 📁 Project Organization

Each training day has its own folder.

```text
HCL-Training-Handson/
│
├── README.md
│
├── Day1/
├── Day2/
├── Day3/
├── ...
├── Day19/
├── Day20/
├── Day21/
├── Day22/
└── Day23/
```

Individual days may contain:

- Source code and project files
- Practical exercises
- Database scripts
- Configuration files
- Project-specific documentation

For larger projects, an individual `README.md` is maintained inside the project folder to explain its features, technologies, setup, and implementation.

## ➕ Adding Future Training Days

To maintain consistency, follow this simple approach whenever a new training day is completed.

**Step 1:** Create a new folder.

```text
Day23/
```

**Step 2:** Add the day's exercises or projects.

```text
Day23/
├── ProjectName/
├── Exercises/
└── README.md
```

**Step 3:** Add a new entry to the Daily Training Projects table.

Example:

```markdown
| Day 23 | New Project Name | [View](Day23/) |
```

**Step 4:** Commit and push the changes.

```bash
git add .
git commit -m "Add Day 23 hands-on practice"
git push origin main
```

This keeps the repository organized and makes future updates straightforward.
